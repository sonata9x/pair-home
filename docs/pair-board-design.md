# 페어홈 갤러리·로그 게시판 설계

## 공통 원칙

- 두 게시판은 그누보드의 글쓰기 권한, 비밀글, 첨부파일, 삭제 흐름을 유지하는 독립 스킨으로 만든다.
- 메인의 `pair_home_grid_document`에서 사이트 대표색과 기본 테마를 읽어 게시판에도 적용한다. 프로필 데이터는 게시판에서 사용하지 않는다.
- 마크업은 하나만 유지하고 `data-theme="flat|line|bold|soft|pixel|glass"`와 CSS 변수로 테마를 바꾼다.
- 테두리 굵기는 위젯과 동일하게 CSS px 단위로 고정한다. 도트 테마는 직각 모서리, Galmuri11, 검정 픽셀 테두리와 가까운 하드 그림자를 사용한다.
- 관리자·작성자 설정 버튼은 점 세 개 아이콘으로 통일한다. 버튼은 이미지 정보를 가리지 않는 오른쪽 위에 둔다.

## 1. 갤러리 게시판

### 화면 구조

갤러리는 별도 프로필·사이드바 없이 게시판 본문 전체 폭을 이미지 영역으로 사용한다. 바깥쪽에는 페이지 제목과 최소한의 필터·업로드 버튼만 두고, 그 아래는 원본 이미지 비율을 보존하는 masonry 레이아웃으로 채운다. 이미지 수가 적을 때도 한쪽에 불필요한 빈 프로필 칸이 생기지 않으며, 넓은 작품은 전체 영역 안에서 더 큰 폭을 사용할 수 있다. 모바일 전환은 전체 위젯 최적화 단계에서 함께 처리한다.

한 게시글을 한 작품으로 취급한다. 한 작품에 여러 장을 올릴 수는 있지만, 목록의 대표 이미지는 썸네일 또는 첫 번째 첨부 이미지다. 이 규칙은 작품별 설명·수정 버튼·라이트박스의 소유 관계를 명확하게 유지한다.

### 카드 동작

- 이미지는 `object-fit: cover`로 강제하지 않고 원본 비율로 표시한다.
- hover 또는 키보드 focus 시 이미지 아래쪽에 `rgba(0,0,0,.72)` 정보 패널을 겹친다.
- 정보 패널에는 작품명, 짧은 설명, 날짜·크레디트를 표시한다.
- 카드를 클릭하면 페이지 이동 대신 중앙 라이트박스를 연다. 원본 비율을 유지하며 최대 `90vw × 86vh` 안에 표시한다.
- 라이트박스는 ESC, 바깥 영역 클릭, 닫기 버튼으로 닫는다. 열려 있는 동안 배경 스크롤을 잠근다.
- 관리자 또는 작성자에게만 카드 오른쪽 위 점 세 개 버튼을 표시한다. 1차 구현은 기존 수정 페이지로 연결하고, 이후 필요하면 설명만 바꾸는 인라인 팝업으로 확장한다.

### 데이터 매핑

| 저장 위치 | 용도 |
| --- | --- |
| `wr_subject` | 작품명 |
| `wr_content` | hover와 라이트박스에 표시할 작품 설명 |
| `wr_1` | 작가·커미션 크레디트 |
| `wr_2` | 작품 날짜 또는 업로드 표기일 |
| `wr_3` | 대표 이미지 대체 텍스트 |
| `wr_4` | 목록 크기 힌트 `normal|wide` |
| `wr_img` / 첫 첨부 | 대표 이미지 |
| 첨부파일 `bf_content` | 장별 캡션 |

`wide`는 masonry에서 넓은 칸을 우선 배정하는 힌트일 뿐 이미지 비율을 바꾸지 않는다. 자유배치는 사용자가 각 작품의 비율과 `normal/wide`를 선택하고, 브라우저가 빈 공간을 자연스럽게 메우는 방식으로 시작한다. 완전한 좌표 드래그 배치는 게시물 추가·삭제 때 빈 구멍이 많이 생기므로 1차 범위에서 제외한다.

## 2. 로그 게시판

### 목록 카드

목록의 대표 이미지만 항상 16:9 세션카드 썸네일로 표시한다. 업로드 시 목록용 확대와 가로·세로 초점을 지정하며 원본 파일은 별도로 보존한다. 카드에는 다음 네 항목만 표시한다.

1. 시나리오명
2. 라이터
3. 플레이타임 · 플레이 날짜

### 상세 상단 구성

상세 화면의 제목 영역에는 시나리오명을 표시하되, HTML 로그 본문 앞에 삽입되는 설정 요소는 다음 세 종류로 제한한다. 값이 없는 요소는 출력하지 않는다.

1. 세션카드 원본 이미지
2. 개요
3. 대기 BGM
4. HTML 로그 본문

상세 세션카드는 16:9로 자르지 않는다. 콘텐츠 영역의 지정된 최대 가로폭에 맞춰 `width: 100%; height: auto`로 축소하고 원본 비율과 전체 화면을 그대로 보여준다. 따라서 세로형이나 정사각형 카드도 위아래가 잘리지 않는다. 목록의 16:9 크롭 설정은 상세 이미지에는 적용하지 않는다.

로그 본문과 시나리오명·라이터·플레이타임·날짜는 게시 후 수정 기능을 제공하지 않는다. 점 세 개 설정에서는 세션카드 원본, 목록용 카드 초점, 개요, 대기 BGM과 BGM 재생에 필요한 플레이리스트만 관리한다. 라이터·플레이타임·날짜는 목록 정보로 저장하지만 HTML 본문 앞에 별도 정보 블록으로 반복하지 않는다.

### 기본 데이터 매핑

| 저장 위치 | 용도 |
| --- | --- |
| `wr_subject` | 시나리오명 |
| `wr_1` | 라이터 |
| `wr_2` | 플레이타임 |
| `wr_3` | 플레이 날짜 |
| `wr_4` | 예약 필드 |
| `wr_5` | 짧은 개요 |
| `wr_6` | 대기 BGM 트랙 키 |
| `wr_7` | 원본 HTML 파일명 |
| `wr_8` | 임포트 스키마 버전 |
| `wr_9` | 목록 16:9 썸네일 전용 초점 `zoom|x|y` |
| `wr_img` / 첫 첨부 | 세션카드 원본 |
| `wr_content` | 정리된 HTML 로그 본문 |

플레이리스트는 여분 필드에 JSON으로 넣지 않는다. URL·제목·아티스트·마커가 늘어나면 255자 제한을 넘기므로 별도 테이블을 사용한다.

### 플레이리스트 테이블

`{G5_TABLE_PREFIX}pair_log_track`

| 열 | 설명 |
| --- | --- |
| `id` | 기본키 |
| `bo_table`, `wr_id` | 로그 식별자 |
| `track_key` | 대기 BGM 및 본문 마커가 참조하는 고유 키 |
| `title`, `artist` | 표시 정보 |
| `audio_url`, `cover_url` | 음원·표지 |
| `sort_order` | 플레이리스트 순서 |

실제 테이블명은 설치의 `G5_TABLE_PREFIX`를 사용하므로 현재 로컬 설정에서는 `ra0_pair_log_track`이 된다. 대기 BGM 여부는 별도 열을 두지 않고 게시글의 `wr_6`이 `track_key`를 참조한다.

### HTML 업로드와 BGM 위치 지정

1. 업로드 전 HTML에서 BGM이 들어갈 위치에 `<!-- PAIR_BGM:chapter-2|2 CHAPTER BGM -->` 형태의 주석 마커를 넣는다. `|` 뒤 라벨은 생략할 수 있다.
2. 작성 화면에서 `.html` 파일을 선택하고 플레이리스트를 `키|곡명|아티스트|음원 URL|표지 URL` 형식으로 입력한다.
3. 저장 시 실행 코드는 제거하지만 `PAIR_BGM` 주석 마커는 유지한다.
4. 출력 시 서버가 마커의 키와 플레이리스트를 연결해 사이트가 만든 BGM 플레이어로 교체한다. 업로드 HTML이 임의 플레이어 HTML을 만들 수는 없다.

로그를 게시한 뒤 정리된 HTML 본문은 잠근다. 본문의 BGM 위치도 함께 고정되며, 설정 화면에서는 같은 마커 키에 연결되는 플레이리스트 곡만 바꿀 수 있다. 새 위치가 필요하면 새 글로 다시 올리는 것을 원칙으로 한다.

### HTML 안전 경계

현 코드의 `html_purifier()`는 실제 필터를 하지 않으므로 그대로 출력하면 안 된다. 로그 임포터에서 다음 규칙을 별도로 적용한다.

- 제거: `script`, `iframe`, `object`, `embed`, `form`, `input`, `button`, `meta`, `base`, 외부 `link`
- 제거: `on*` 이벤트 속성, `javascript:`, `data:text/html`, `srcdoc`
- 허용: 문서 구조, 텍스트 서식, 표, 이미지, 안전한 링크와 제한된 스타일
- 링크에는 `rel="noopener noreferrer"`를 강제한다.
- 서버에는 정리된 HTML 복사본과 원본 파일명만 저장하고, 업로드 임시 원본은 보존하지 않는다.
- 임포트된 CSS와 본문은 sandbox iframe에 격리해 사이트 헤더·설정 버튼을 덮어쓰지 못하게 한다.

### BGM 동작

- 한 로그 안에서는 동시에 한 곡만 재생한다.
- 대기 BGM과 본문 BGM도 같은 플레이리스트 상태를 공유한다.
- 본문 마커에는 곡명, 재생 버튼, 얇은 진행 바만 표시하고 전체 플레이리스트는 상단 또는 우측 드로어에서 연다.
- 메인의 BGM과 로그 BGM이 함께 존재할 때도 새 곡을 재생하면 기존 곡을 정지시키는 공통 이벤트를 사용한다.
- 자동재생은 사용하지 않는다.

## 3. 테마별 표현

| 테마 | 게시판 표현 |
| --- | --- |
| Flat | 흰 바탕, 테두리 없음, 대표색 아이콘 |
| Line | 1px 대표/개별 테두리, 그림자 없음 |
| Bold | 검정 2px 테두리, 플랫 내부 구성 |
| Soft | 옅은 대표색 바탕, 부드러운 그림자 |
| Pixel | 직각, Galmuri11, 검정 픽셀 테두리, 2~3px 하드 그림자 |
| Glass | 반투명 흰 바탕, backdrop blur, 얇은 밝은 테두리 |

갤러리의 검정 hover 패널과 로그 HTML 본문은 가독성을 위해 테마색을 직접 덮지 않는다. 대신 버튼, 캡션 라벨, 진행 바, 포커스 링에 대표색을 사용한다.

## 4. 구현 순서

1. 공통 게시판 테마 로더
2. `pair_gallery` 목록, 라이트박스, 작성·수정 폼
3. `pair_log` 목록의 16:9 썸네일과 상세 원본 비율 세션카드
4. HTML 임포터와 불변 본문 저장
5. 플레이리스트·cue 테이블 및 BGM 플레이어
6. 여섯 테마 시각 검증
7. 실제 게시판 생성·스킨 지정 후 통합 테스트
8. 전체 위젯과 함께 모바일 최적화

## 5. 1차 완료 기준

- 갤러리의 서로 다른 세로·가로 이미지가 비율 왜곡 없이 배치된다.
- hover/focus 정보, 중앙 라이트박스, 작성자 설정 버튼이 키보드에서도 동작한다.
- 로그 목록 카드는 모두 16:9이며 목록 전용 업로드 초점이 저장된다. 목록에는 시나리오명·라이터·플레이타임·날짜만 표시된다.
- 상세 세션카드는 가로폭만 제한하고 원본 비율 전체가 보인다.
- 세션카드·개요·대기 BGM이 있을 때만 HTML 본문 위에 순서대로 나타난다. 다른 메타데이터 블록은 본문 위에서 반복하지 않는다.
- 업로드 HTML의 스크립트와 이벤트 속성이 실행되지 않는다.
- 대기 BGM, 본문 BGM, 플레이리스트 중 하나를 재생하면 나머지는 정지한다.
- 로그 본문 수정 링크는 제공하지 않고 설정 링크만 제공한다.
- 모든 화면이 메인의 여섯 테마와 대표색을 상속한다.
